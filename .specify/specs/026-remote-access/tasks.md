## How to work (applies to every task)
- Read first: `.specify/memory/constitution.md`, `docs/architecture.md`, `.specify/specs/026-remote-access/spec.md` and `plan.md`, `docs/context.md` (the "remote access" terms).
- **Test first, seen failing for the right reason.** Create the exported signature with a wrong or empty body, write the test, run it (`pnpm exec vitest run tests/<file>`), see an assertion fail (not "module not found"), then write the code. Name each test with its AC id: `it('AC-4.5 …')`.
- Each task ends with `pnpm run check:fast` green. Never `--no-verify`, never `biome-ignore` without a written reason, never lower a threshold. pnpm only.
- Style: no `;`, single quotes, English identifiers, user-facing text only through dictionary keys (`src/shared/i18n/{es,en}`; the phone's through its own dictionary), comments only for the why. Commits `type(area): summary`, no Claude co-author line.
- Layers (`docs/architecture.md`, `tests/support/arch.ts`): `shared` imports nothing; `coordinator` never imports `main`/`renderer` and never `electron` outside `index.ts`; `main` never imports `coordinator`; the phone client imports only itself and `src/shared/remote/`.
- Secrets never in logs, audit entries, errors, fixtures or prompts (BR-15). Tests use fake keys generated on the spot.
- Files that many tasks touch (`src/shared/types.ts`, `src/shared/i18n/{es,en}.ts`, `src/coordinator/index.ts`, `src/main/index.ts`, `src/main/messages.ts`, `src/renderer/src/components/SettingsDialog.tsx`, `src/remote-client/App.tsx`, the PWA dictionaries): **two tasks that touch the same one never run in parallel.**
- A task whose diff touches only glue (wiring, UI) says so; commit it with `[no-tests: <reason>]` as `scripts/require-tests.mts` allows, and its logic is tested in the earlier task it names.
- Reuse, do not rebuild: `src/shared/audit.ts` (`audit()`, `AuditEvent`, `throttle`), the channel pattern of `src/coordinator/channels/telegram.ts` (`TelegramDeps` injection, a pure `authorizeChat`-style function, `texts.ts`), `src/main/guard.ts` (pure decision + dialog in `main`), `src/main/settings.ts` + `safeStorage` through `HostRequest` `secret.seal`/`secret.open`, the tool definitions in `src/coordinator/tools/home.ts` and the approval broker/`authorize` in `src/coordinator/approval.ts`, `isPrivateHost` in `src/coordinator/tools/web.ts`, the `qrcode` package, `src/coordinator/privacy.ts`.
- UI tasks (T36 to T39, T40 to T45) load the `console-ui` and `umbra-ui` skills first and use only their tokens and components (section on the PWA and the tab below).
