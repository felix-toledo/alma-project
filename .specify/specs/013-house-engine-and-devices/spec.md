# 013 — Casa: engine and devices

## 1. Summary
"Casa" is Alma's domotics feature. Alma runs a Home Assistant (HA) as its **engine**, either one it installs and manages itself inside a hidden WSL2 distro called `alma-home`, or one the person already has (URL + token). On top of it Alma shows the house's **devices** (lights, plugs, covers, fans, climate, speakers, cameras, locks, alarms), lets the person add a device of any brand HA knows through step-by-step forms (QR codes, accounts, links), rename, move or remove it, and control it from the Casa window or by asking an agent (chat, voice, Telegram, WhatsApp). Locks, alarms and gates always need the person's approval. The state shown is live.

## 2. Problem and goal
Smart devices from different brands (Tuya/Smart Life, eWeLink/Sonoff, Tapo/ONVIF, Hue, Chromecast…) each need their own app. The goal: one place where the person installs nothing technical, adds any device, and says "prendeme la luz de la cocina" and it happens, with the sensitive things (locks, alarms, gates) never acting without the person's yes.

## 3. Scope
**In:**
- The **engine**: managed (WSL2 distro `alma-home`: install, start, stop, uninstall, health/recovery, adoption of an engine left running) and external (URL + token); the status it reports; Settings → Casa (engine card, mode, connected accounts).
- The **hub** (`hub.ts`, `ha.ts`): the connection to HA, mirrored states and registries, live snapshot, calling services, renaming/moving/removing devices, areas used by devices, integrations list and config entries, history.
- The **device model** (`model.ts`, `src/shared/home.ts` device parts): how HA entities become "things", kinds, on/off, sensitivity, name search.
- **Adding devices** (`flow.ts`, `AddDevice.tsx`): brands, config flows, forms, QR, external links, menus, progress.
- **Device tools**: `home_overview`, `home_find`, `home_control`, `home_secure_control`, `home_call_service`, `home_add_device`, `home_edit_device`, `home_remove_device`, `home_history`.
- The **Casa view device side**: Dispositivos tab, device panel, tap-to-toggle, sidebar, engine card, live updates.

**Out (and why):** everything below belongs to [`../014-house-plan-cameras-and-rules/spec.md`](../014-house-plan-cameras-and-rules/spec.md):
- the floor plan (`plan.ts`, `FloorPlan.tsx`, plan editing, import from Excalidraw or an image, `home_plan`, `home_plan_edit`, `home_plan_from_drawing`, `home_plan_from_image`, auto-placing devices, savePlan's area sync);
- cameras and vision (`camera_look`, `camera_photo`, `camera_watch`, `look_at_image`, camera stills and live stream, vision model setting);
- scenes/modes (`home_scene`, `home_modes`, the mode buttons) and rules (`home_rules`, HA automations, judgment rules, `triggers.ts`, `RulesPanel`, the agent that answers rules).
Where a 013 mechanism is shared (the hub's scene/automation/camera methods, `home.snapshot` carrying scenes and automations), this spec only says that it exists. Other neighbors: tool approvals in [`../004-approvals/spec.md`](../004-approvals/spec.md); Settings dialog in [`../006-settings/spec.md`](../006-settings/spec.md); channels in [`../010-telegram/spec.md`](../010-telegram/spec.md), [`../011-whatsapp/spec.md`](../011-whatsapp/spec.md) and voice [`../019-voice/spec.md`](../019-voice/spec.md); secrets/privacy [`../022-security-and-privacy/spec.md`](../022-security-and-privacy/spec.md).

## 4. Users and stories
- **US-1** As a person, I want Alma to install the engine with one button, so that I never need to know what Home Assistant is.
- **US-2** As a person, I want the engine to start with Alma, stop when Alma closes, and recover by itself, so that the house just works.
- **US-3** As a person who already runs Home Assistant, I want to connect Alma to it with a URL and a token.
- **US-4** As a person, I want to see all my devices grouped by room with their live state.
- **US-5** As a person or an agent, I want to control lights, plugs, fans, covers, climate and speakers by name, room or kind, without being asked for permission.
- **US-6** As a person, I want locks, alarms, sirens and gates to always ask me first, whatever approval mode I use.
- **US-7** As a person, I want to add a device of any brand through a guided form (or by asking Alma), including QR codes and external pages.
- **US-8** As a person or an agent, I want to rename, move to another room, or remove a device.
- **US-9** As a person, I want to operate a device from its panel (brightness, color, volume, position…) and from a tap on the Dispositivos tab.
- **US-10** As a person, I want the state in the window to follow reality (also when changed from another app), and to see what happens when the engine is not ready.
- **US-11** As a person, I want to turn the feature on or off and see/remove the connected brand accounts in Settings → Casa.
- **US-12** As an agent, I want to look up recent history of a device.

## 5. Acceptance criteria

### Engine: install (US-1)
- **AC-1.1** (US-1) Given Windows with WSL2 and no `alma-home` distro, when the person presses "Instalar el motor" (Casa or Settings), then the engine goes through `installing` with a step text and a 0–1 progress, imports the distro, configures it and ends `ready` with the URL and HA version. [gap] (the real install is only exercised by the opt-in live test, see AC-2.5)
- **AC-1.2** (US-1) Given WSL2 is not available (`wsl --status` fails, or the platform is not Windows), when install is requested, then the state is `unsupported` with "Abrí PowerShell como administrador, corré «wsl --install», reiniciá y probá de nuevo." and the request fails. [gap]
- **AC-1.3** (US-1) Given less than 6.5 GB (`NEEDED_BYTES`) free in the data folder, when the distro must be installed, then install fails with "Falta espacio en disco: hacen falta unos 7 GB libres y hay N GB." before downloading anything. [gap]
- **AC-1.4** (US-1) Given the crane download does not match its pinned SHA-256, when install runs, then it fails with "La descarga de crane no coincide con el checksum esperado." and crane is not used. [gap]
- **AC-1.5** (US-1) Given an install in progress, when the engine is stopped (or the feature turned off), then the download/import is aborted and the state returns to `missing`. [gap]
- **AC-1.6** (US-1) Given SonoffLAN (eWeLink) cannot be downloaded during install, when install finishes, then the install still succeeds (the failure is only logged to the console) and eWeLink is not offered by HA. [gap]
- **AC-1.7** (US-1) Given an install fails (download, import, boot), when it ends, then the state is `error` with the message, and "Reintentar" (`home.start`) starts the already installed engine. [gap]
- **AC-1.8** (US-1) [manual] The first install downloads about 1.2 GB, takes about 10 minutes, and the window keeps working meanwhile; the Casa card and Settings show the step and a progress bar. Checked by running the install on a clean machine and watching the card.
- **AC-1.9** (US-1) Given the engine config is written, then it contains `default_config:`, includes for `automations.yaml`/`scenes.yaml`/`scripts.yaml`, the chosen port, the time zone, the language of `language` (`es` in the cited test, which runs under `es`), and the ffmpeg wrapper path. Test: tests/home.test.ts › "la configuración del motor incluye las reglas, los modos y el puerto"
- **AC-1.10** (US-1) Given wsl.exe prints UTF-16 and Linux commands print UTF-8, when output is decoded, then both read correctly. Test: tests/home.test.ts › "decodeWsl entiende el UTF-16 de wsl.exe y el UTF-8 de Linux"

### Engine: lifecycle, recovery, adoption (US-2)
- **AC-2.1** (US-2) Given the feature is enabled, mode managed, the distro exists and the engine is `off`/`missing`, when Alma starts (or settings change), then the engine boots HA, creates Alma's owner account on the first start, and reaches `ready`. [gap]
- **AC-2.2** (US-2) Given HA's process exits unexpectedly while `ready`, when fewer than 3 restarts happened in the last 10 minutes, then the state becomes `starting` with "Home Assistant se detuvo; reiniciando" and it is started again; at the next exit the state is `error` ("Home Assistant se detuvo varias veces (código N)…" plus the last log lines). [gap]
- **AC-2.3** (US-2) Given the default port 8123 is busy and Alma holds credentials whose URL is `http://127.0.0.1:<port>` and that HA answers `/api/config`, when the engine starts, then it **adopts** that running engine (`ready`, no second process) instead of starting one. [gap]
- **AC-2.4** (US-2) Given port 8123 is busy by something else, when the engine starts, then it uses 18123 (saved in `engine.json`); if that is busy too the state is `error` "El puerto 18123 está ocupado por otro programa.". [gap]
- **AC-2.5** (US-2) Given a real machine with WSL2 (opt-in, `ALMA_HOME_INSTALL=1`), when the engine installs, starts, stops, starts again and is uninstalled, then the token is the same on the second start and the distro is gone after uninstall. Test: tests/home-live.test.ts › "instala, arranca, crea la cuenta, se apaga y vuelve a arrancar" (skipped unless `ALMA_HOME_INSTALL` is set)
- **AC-2.6** (US-2) Given Home Assistant already has an owner account Alma does not know (no saved credentials), when the engine starts, then it fails with "Home Assistant ya tiene una cuenta que Alma no conoce. Reinstalá el motor desde Configuración → Casa.". [gap]
- **AC-2.7** (US-2) Given HA does not answer within 8 minutes of launch, when booting, then startup fails with "Home Assistant no arrancó a tiempo." and the process is killed (`wsl --terminate`). [gap]
- **AC-2.8** (US-2) Given a managed engine is running, when Alma quits, then HA is asked to stop through its own `homeassistant.stop` service, the process gets up to 20 s to exit (8 s fixed wait when it was adopted), and is then terminated. [gap]
- **AC-2.9** (US-2) Given the engine is stopped by the person ("Detener"), when it ends, then the state is `missing` if the feature is enabled (`off` if disabled). [gap]
- **AC-2.10** (US-2) Given "Desinstalar" is confirmed, when it runs, then the engine stops, the distro is unregistered, `vm/`, `auth.json` and `engine.json` are deleted, and the plan and rules are kept. [gap]
- **AC-2.11** (US-2) Given the feature is turned off in Settings, when settings sync, then the running engine is stopped and the state is `off`. [gap]
- **AC-2.12** (US-2) Given an engine state change, when it happens, then the coordinator emits `home.engine` with the status, the hub connects when the state becomes `ready`, and the hub disconnects (and an empty snapshot is emitted) when the state becomes `off`/`missing` or leaves `ready` while connected. [gap]

### External Home Assistant (US-3)
- **AC-3.1** (US-3) Given a URL not starting with `http://` or `https://`, when "Conectar" is pressed, then it fails with "La dirección tiene que empezar con http:// o https://". [gap]
- **AC-3.2** (US-3) Given a URL and token that HA accepts (`GET /api/config` works), when "Conectar" is pressed, then the token is saved sealed with the OS keychain, trailing slashes are removed from the URL, the state is `ready` with HA's version, and the Settings card shows "Conectado.". [gap]
- **AC-3.3** (US-3) Given a wrong URL or token, when "Conectar" is pressed, then the message "No se pudo entrar a <url>: …" is shown and nothing is saved as credentials. [gap]
- **AC-3.4** (US-3) Given mode external, enabled, and no URL or no saved credentials for that URL, when the engine syncs, then the state is `missing` and the Casa card says "Falta la dirección y el token de tu Home Assistant. Se cargan en Configuración → Casa.". [gap]
- **AC-3.5** (US-3) Given mode external with saved credentials, when Alma starts and HA answers, then the state goes `starting` ("Conectando con Home Assistant") then `ready`; if it does not answer the state is `error` with the message. [gap]

## 6. Business rules
- **BR-1** The managed engine is Home Assistant **2026.10.1** (`HA_VERSION`), the official container image exported for `linux/amd64` with crane v0.22.1 (no Docker) and imported with `wsl --import <distro> <vm folder> <tar> --version 2`. (src/coordinator/home/engine.ts)
- **BR-2** The downloaded crane archive must match the pinned SHA-256 before it is unpacked, and it is unpacked with Windows' own `System32\tar.exe`. (engine.ts)
- **BR-3** Installing needs 6.5 GB free (`NEEDED_BYTES`) in the data folder; the UI texts say "unos 1,2 GB" to download, "unos 3 GB" on disk, "unos 10 minutos"; the progress bar assumes a 2.6 GB rootfs and a 4-minute import. (engine.ts, HomeView.tsx, HomeSettings.tsx)
- **BR-4** The distro is named `alma-home` (overridable with `ALMA_HOME_DISTRO`); HA listens on 8123, else 18123; boot timeout is 8 minutes. (engine.ts)
- **BR-5** HA runs as a child process `wsl.exe -d <distro> --exec /bin/sh /usr/local/bin/alma-ha.sh` with a clean environment; `configuration.yaml` is rewritten at every start (name Casa, metric, the language of `language` (also the language of the HA user Alma creates), host time zone, http on all interfaces, recorder purge 7 days, logger warning) and `automations.yaml`, `scenes.yaml`, `scripts.yaml` are created as `[]` if missing. (engine.ts)
- **BR-6** RTSP cameras use a wrapper around ffmpeg that forces TCP, because WSL's NAT drops UDP. (engine.ts)
- **BR-7** SonoffLAN v3.13.1 is copied into `/config/custom_components/sonoff` at install; its failure does not fail the install. (engine.ts)
- **BR-8** At most 3 automatic restarts in 10 minutes; the next unexpected exit puts the engine in `error`. (engine.ts)
- **BR-9** Alma's owner account in the managed engine is named `alma`, has a random 48-hex-character password, and a long-lived token of 3650 days; both are stored sealed. (ha.ts, engine.ts)
- **BR-10** Uninstall removes the distro, `vm/`, `auth.json`, `engine.json`; it keeps `crane.exe`, the plan and the rules. (engine.ts)
- **BR-11** Heavy engine operations (install, start, connect, restart) are serialized: a request while one is running returns the running one. (engine.ts)
- **BR-12** A device is "sensitive" if it is a lock or alarm (incl. siren), or a cover with device class garage, gate or door. Sensitive things are controlled only through `home_secure_control` (risk `publish`, asks on every call). (src/shared/home.ts, tools/home.ts, approval.ts)
- **BR-13** Risk classes: read (`home_overview`, `home_find`, `home_history`), home (`home_control`), write (`home_call_service`, `home_add_device`, `home_edit_device`, `home_remove_device`), publish (`home_secure_control`). `home` never asks and is only refused in the "blocked" approval mode. (tools/home.ts, approval.ts, tools/types.ts)
- **BR-14** Controllable domains: light, switch, input_boolean, camera, media_player, cover, fan, climate, humidifier, water_heater, lock, alarm_control_panel, siren, valve, vacuum, lawn_mower. Everything else (sensor, binary_sensor…) is a sensor of its device. (src/shared/home.ts)
- **BR-15** Hidden (`hidden_by`), disabled, diagnostic/config-category and stateless entities, and disabled devices, never show. (model.ts)
- **BR-16** Integrations treated as plumbing (not listed as connected accounts): sun, radio_browser, google_translate, met, backup, hassio, cloud, go2rtc, shopping_list. (hub.ts)
- **BR-17** Constants: WebSocket/REST/command timeout 30 s; history request 45 s; state snapshot debounce 300 ms; registry reload debounce 500 ms; reconnect backoff 1 s × 2^n capped at 30 s; flow progress poll 1.5 s × 40; light tool pause 700 ms (900 ms secure). (ha.ts, hub.ts, flow.ts, tools/home.ts)
- **BR-18** Defaults for the setting: enabled false, mode managed, externalUrl '', mirrored false. (src/shared/defaults.ts)
- **BR-19** Home tools are offered to an agent only when the feature is enabled and the agent is not working in a company. (src/coordinator/agent.ts)
- **BR-20** Colors by name: rojo, verde, azul, amarillo, naranja, violeta/morado, rosa, celeste, blanco; temperatures: cálida 2700 K, neutra 4000 K, fría 6000 K. (tools/home.ts)

- **BR-21** Remote clients reach the house only through the remote channel. Sensitive house actions from a paired phone need a passkey step-up: a 60-second single-use assertion bound to the exact device, thing and action, fail closed (spec 026 BR-24). Everyday control from the phone reuses `home_control` with the same refusals.

## 7. Constraints and risks
- **Layers:** `src/shared/home.ts` (types, `DEVICE_DOMAINS`, `isSensitive`, popular integrations, flow types); `src/coordinator/home/{engine,ha,hub,flow,model,index}.ts` (the engine runs in the coordinator process, not in main; main only seals/opens secrets); `src/coordinator/tools/home.ts`; `src/renderer/src/home/{HomeView,DevicePanel,AddDevice,HomeSettings,homeLib,useHome}.tsx|ts`; settings in `src/main/settings.ts` (merge `home: {...base.home, ...stored.home}`) and `src/shared/defaults.ts`.
- **Messages:** window → coordinator requests `home.status|install|start|stop|uninstall|connectExternal|advanced|snapshot|control|thing.update|thing.remove|integrations|entries|flow.start|flow.step|flow.abort|entry.remove` (plus plan/rules/camera ones owned by 014); coordinator → window events `home.engine`, `home.snapshot`, `home.flow` (plus `home.plan`, `home.rules`); coordinator → main host requests `secret.seal` / `secret.open`.
- **Persistence:** `<data>/home/auth.json` (sealed token/password), `<data>/home/engine.json` (port), `<data>/home/crane.exe`, `<data>/home/vm/` (the distro's disk), temporary `rootfs.tar` and `crane.tgz`; HA's own data inside the distro (`/config`). Local storage key `alma.home.tab` (per-viewer convenience).
- **Security / privacy:** HA's long-lived token and the owner password are sealed with the OS keychain; the owner password is shown in clear on request. Account passwords and codes for brands (Tuya user code, eWeLink password) travel from the person to HA; when an agent runs `home_add_device` the tool tells the agent that the person types them, which means they pass through the chat and the model provider. The engine listens on `0.0.0.0` inside WSL (reachable from the Windows host; LAN exposure depends on WSL networking). `home_call_service` is a general back door (BR-13). Entries for `docs/security/` should cover the HA engine, the crane/SonoffLAN downloads from GitHub/ghcr.io, and the stored owner credentials.
- **Platform:** Windows 10/11 with WSL2 and virtualization; other platforms are `unsupported`. Network is WSL's NAT, so LAN discovery (mDNS/SSDP) does not work; brands are added by account, cloud or IP. The `mirrored` setting exists but nothing in the code reads it. Downloads: crane and SonoffLAN from GitHub, the HA image from `ghcr.io`. The engine is not a long-term background service: it stops when Alma quits, so rules do not run then.
- **Tools exposed (all `standalone`):** see BR-13 for risks.
