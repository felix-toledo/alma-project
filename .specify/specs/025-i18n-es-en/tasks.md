Conventions for every task:
- Phases are ordered A to H; each phase ends with `pnpm run check:fast` green, and so does each task inside it.
- Tests live in the files named in `plan.md` §6 and name the AC (`it('AC-1.1 …')`). Existing Spanish assertions are never edited except as BR-25 allows (English tool errors and results, the old wake phrase).
- **UI task** = touches `src/renderer`: load the `console-ui` and `umbra-ui` skills first; reuse their components and tokens by name, invent none. Spanish text moves into `src/shared/i18n/es/<area>.ts` verbatim (rioplatense), the English goes into `en/<area>.ts` (US English), the JSX calls `t('area.key')`, and the task deletes its files' lines from the ratchet baseline in `tests/support/i18n.ts`. The task's check: parity test, ratchet, `pnpm run typecheck`, and a manual run with the `run` skill in both languages (AC-2.1).
- **[P:x]** marks tasks that can run in parallel with the others of group `x` once their prerequisite is done. Tasks without a mark run alone, in order. Tasks that edit the same file are never in the same group.
